# Phase-0J read-only Influx capacity gate — operator usage

**Status:** evidence collection and offline review only; no production, retention, access or storage mutation. This drop-in must be integrated through the normal PlatformCompute master helper before use. The Phase-0I MarketData administrative-read block is unchanged.

1. Confirm the *actual* DEV Influx guest, hypervisor, data path, WAL path and endpoint mapping from inventory. Do **not** derive those facts from `192.168.200.27` or attempt automatic SSH discovery. Obtain approved read access. On that actual host, where the accepted repo source is present, copy `config/phase0j_scope.template.json` to an **external** working path (not under the repo) and fill it with existing verified, non-secret scope facts. `backup_path_local=false` means `backup_path=null`, and the backup remains unresolved pending owner evidence. Never place credentials or secret configs in the scope.
2. Run `scripts/run_phase0j_marketdata_influx_capacity_gate_readonly.sh collect --scope /approved/external/scope.json --output /approved/external/snapshot.json` from the accepted `origin/main` checkout on the actual host. The destination parent must already exist and must not be inside Influx data or WAL paths. The command performs no network calls or Influx API calls, does not use sudo, and does not discover hosts. A collector PASS means a bounded snapshot exists, **not** approval.
3. On an accepted PlatformCompute checkout, prepare an **external** `assessment.json` from `config/phase0j_assessment.template.json` using only independently documented and owner-authorized measurements. Provide complete bucket inventory, redacted retention evidence, two attributable engine/index stored-byte growth windows, measured peak day and WAL/compaction reserves, sharing proof, backup capacity and DR dependency, concurrency/latency sources, stop conditions, bounded batch policy and explicit Platform reviewer decision. Missing fields should remain null, not guessed.
4. Run `scripts/run_phase0j_marketdata_influx_capacity_gate_readonly.sh evaluate --snapshot /approved/external/snapshot.json --assessment /approved/external/assessment.json --output-root /approved/external/evidence`. This is offline and emits one immutable SHA-256/manifest-verified ZIP with its source snapshot, provenance index, forecast/gate, receipt and MarketData + DR handoffs. It does **not** authorize a backfill or claim DR restore acceptance.

`APPROVED` requires the measured prerequisites and an explicit Platform reviewer signoff. `NOT_APPROVED` is only emitted for an explicit documented reviewer decision or a measured capacity/inode/backup-headroom deficit. Otherwise the disposition is `UNVERIFIED` and batch/stop limits remain unset. Segment A and B outputs are forecasts only, even if Segment C is approved.

**Important limitations:** Mount and instantaneous disk counter evidence does not establish peak latency or sustained throughput. If DEV and LIVE share infrastructure, retain `UNVERIFIED` unless shared-bottleneck controls are separately documented and signed. Offline source references are not independently validated external records; owner review and DR acceptance remain necessary. Never run the collector on an assumed host or query Influx admin endpoints without separate authorization.
